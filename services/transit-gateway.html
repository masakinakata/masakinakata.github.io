ネットワーク

AWS Transit Gateway

多数の VPC、VPN、Direct Connect を 1 か所に集約してつなぐ、リージョン単位のネットワークハブ。ハブ＆スポーク型で推移的なルーティングができる。

構成図

仕組みと主な機能

アタッチメント

  • TGW には VPC、Site-to-Site VPN、Direct Connect ゲートウェイ、他リージョンの TGW（ピアリング）、Connect（SD-WAN 機器との GRE/BGP）をアタッチできる。
  • Direct Connect との接続は トランジット VIF → Direct Connect ゲートウェイ → TGW。

ルートテーブル（関連付けと伝播）

  • 関連付け（association）：アタッチメントから来た通信が、どのルートテーブルで経路を決めるか。
  • 伝播（propagation）：アタッチメントの CIDR を、どのルートテーブルに自動で載せるか。
  • ルートテーブルを分けることで「本番と開発は通信させないが、どちらも共有サービス VPC には届く」といったセグメント分割ができる。

マルチアカウントでの使い方

  • ネットワークアカウントで TGW を作り、AWS RAM で組織や OU に共有する。各アカウントは自分の VPC をアタッチするだけ。
  • 通信を集中検査したいときは、インスペクション VPC（AWS Network Firewall など）を経由させる。このときアタッチメントのアプライアンスモードを有効にして、往復の通信が同じ AZ を通るようにする。

VPC 間接続の比較

方式推移的ルーティング向いている規模・用途
VPC ピアリング不可少数の VPC 同士。データ処理料金がかからず低コスト
Transit Gateway可能数十〜数千の VPC とオンプレミスを集中管理
AWS Cloud WAN可能複数リージョンにまたがるグローバル WAN をポリシーで管理
AWS PrivateLink—（サービス単位）特定のサービスだけを一方向に公開。CIDR が重複していても可

試験で狙われるポイント

  • 「多数の VPC」「相互接続」「集中管理」「運用負荷最小」→ Transit Gateway + RAM 共有。
  • VPC ピアリングは推移的ルーティングができない（A–B、B–C をつないでも A–C は通信できない）。
  • TGW には時間単位のアタッチメント料金と、データ処理料金がかかる。大量データを少数 VPC 間で流すだけならピアリングの方が安い場合がある。
  • EC2 の VPN アプライアンスで組む「トランジット VPC」は古い構成。今はまず TGW を選ぶ。
