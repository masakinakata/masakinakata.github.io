AWS IAM Identity Center

従業員が 1 回のサインインで、組織内の複数の AWS アカウントや業務アプリにアクセスできるようにするサービス（旧 AWS SSO）。既存の社内 ID 基盤と連携できる。

構成図

仕組みと主な機能

ID ソース（いずれか 1 つ）

  • Identity Center ディレクトリ：Identity Center の中でユーザーを直接作る。
  • Active Directory：AWS Managed Microsoft AD、または AD Connector 経由でオンプレミスの AD を使う。
  • 外部 ID プロバイダー：Entra ID や Okta など。認証は SAML 2.0、ユーザーとグループの同期は SCIM。

権限セットと割り当て

  • 権限セット：AWS 管理ポリシー、カスタマー管理ポリシー、インラインポリシー、アクセス許可の境界をまとめたテンプレート。
  • 割り当てると、対象アカウントに AWSReservedSSO_<権限セット名>_… という IAM ロールが自動作成される。
  • 利用者は一時的な認証情報だけを使う。CLI からは aws sso login で取得できる。
  • ユーザーの属性（部署など）を使った ABAC も可能。

運用

  • Organizations と統合されており、管理アカウントではなく委任管理者アカウントから運用するのが推奨。
  • AWS アカウントだけでなく、SAML 対応の業務アプリへの SSO にも使える。

似たサービスとの違い

サービス対象用途
IAM Identity Center従業員複数アカウントや業務アプリへの SSO
IAM の SAML フェデレーション従業員アカウントごとに IdP とロールを設定（数が多いと大変）
Amazon CognitoアプリのエンドユーザーWeb / モバイルアプリのサインアップ・サインイン
IAM ユーザー—長期的な認証情報。人のアクセスには非推奨

試験で狙われるポイント

  • 「従業員」「複数アカウント」「既存の社内 ID で SSO」→ IAM Identity Center。
  • 「入退社を自動反映」→ SCIM。「サインイン」→ SAML。役割の違いを問われる。
  • 「アプリの利用者」の認証なら Cognito。従業員向けと取り違えさせる選択肢に注意。
