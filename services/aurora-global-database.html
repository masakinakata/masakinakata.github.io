データベース

Amazon Aurora Global Database

1 つの Aurora データベースを複数のリージョンにまたがって構成し、ストレージ層で高速にデータを複製する仕組み。リージョン障害に備えた DR と、離れた地域からの低レイテンシーな読み取りに使う。

構成図

仕組みと主な機能

プライマリとセカンダリ

  • プライマリリージョン：読み書きができる唯一のクラスター。
  • セカンダリリージョン：読み取り専用のクラスター。複数のリージョンに置ける。読み取りの負荷分散や、地域ごとの低レイテンシーな参照にも使える。
  • 複製は ストレージ層 で行われるため、binlog などを使う論理レプリケーションより高速で、プライマリ側の性能への影響も小さい。

切り替えの 2 種類

  • スイッチオーバー（計画的）：リージョンが健全なときに、プライマリを別リージョンへ移す。データ損失なし（RPO 0）。メンテナンスや DR 訓練で使う。
  • フェイルオーバー（計画外）：リージョン障害時にセカンダリを昇格させる。複製遅延の分だけデータを失う可能性がある（RPO ≒ 数秒程度）。RTO は通常 数分。

その他の機能

  • 書き込み転送：セカンダリに来た書き込みをプライマリへ転送できる。アプリの接続先を地域ごとに分けやすい。
  • ヘッドレス構成：セカンダリに DB インスタンスを置かずストレージだけ複製しておき、障害時にインスタンスを追加する。コストを抑えられるが RTO は延びる。

試験で狙われるポイント

  • 「リレーショナル DB」「別リージョンへの DR」「RPO が秒〜1 分」→ まず Aurora Global Database を疑う。
  • Multi-AZ やリードレプリカの追加はリージョン内の高可用性であり、リージョン障害の DR ではない。
  • 「全リージョンで書き込みたい（アクティブ/アクティブ）」なら DynamoDB グローバルテーブルが候補。Aurora Global Database の書き込みはプライマリだけ。
  • DNS の切り替えは Route 53 のフェイルオーバールーティング + ヘルスチェック。より確実な切り替え管理には Route 53 Application Recovery Controller。
