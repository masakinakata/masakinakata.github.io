データベース

Amazon RDS Proxy

アプリケーションと RDS / Aurora の間に入るフルマネージドなデータベースプロキシ。DB 接続をプールして使い回すことで、接続数の枯渇を防ぎ、フェイルオーバー時の影響も小さくする。

構成図

仕組みと主な機能

  • 接続プーリングと多重化：クライアントの接続を受け付け、トランザクションの合間に DB 接続を別のクライアントへ使い回す。
  • ピン留め（pinning）：セッション変数の変更など、接続の状態に依存する操作があると、その接続は特定のクライアントに固定され、多重化の効果が下がる。
  • フェイルオーバー時間の短縮：DNS の切り替えを待たずに新しいライターへ接続を張り直す。アプリ側の接続は維持される。
  • 認証：認証情報は Secrets Manager に保存。アプリからは IAM 認証で接続でき、パスワードをコードに持たなくてよい。
  • Aurora では読み取り専用エンドポイントを追加してリーダーに振り分けられる。
  • 対応エンジン：Aurora MySQL / PostgreSQL、RDS for MySQL / PostgreSQL / MariaDB / SQL Server。プロキシは VPC 内に作られ、インターネットからは直接使えない。

試験で狙われるポイント

  • 「Lambda + RDB」「Too many connections」→ RDS Proxy。
  • 「フェイルオーバー時間を短縮」「IAM 認証を強制」「認証情報を Secrets Manager で管理」も RDS Proxy のキーワード。
  • DB インスタンスを大きくして max_connections を増やす案は、一時しのぎで不正解になりやすい。
  • 読み取り負荷が問題なら ElastiCache やリードレプリカ、接続数が問題なら RDS Proxy、と原因で使い分ける。
