Amazon Route 53 Resolver

VPC に標準で備わっている DNS リゾルバー。インバウンド / アウトバウンドの「Resolver エンドポイント」と「転送ルール」を使うと、オンプレミスと AWS の間で双方向に名前解決できる。

構成図

仕組みと主な機能

VPC 標準のリゾルバー

  • VPC CIDR の ベース + 2 のアドレス（例：10.0.0.2）や 169.254.169.253 で利用できる。
  • このアドレスは VPC の外（オンプレミス）からは直接問い合わせできない。そのためにインバウンドエンドポイントがある。

エンドポイントとルール

  • インバウンドエンドポイント：VPC 内に ENI（複数 AZ 推奨）を作り、オンプレミスからの問い合わせを受け付ける。
  • アウトバウンドエンドポイント：VPC からオンプレミスなど外部の DNS へ問い合わせを送り出す。
  • 転送ルール：「どのドメインを、どの DNS サーバーに転送するか」を定義する。AWS RAM で他アカウントに共有し、各 VPC に関連付けられる。

関連機能

  • プライベートホストゾーン：VPC 内だけで使える DNS ゾーン。インバウンドエンドポイントがある VPC に関連付けておく必要がある。他アカウントの VPC とも関連付けできる。
  • Route 53 Profiles：ホストゾーンの関連付けや Resolver ルールなどの DNS 設定をまとめて、多数の VPC やアカウントに一括適用できる。
  • Resolver DNS Firewall：悪性ドメインへの問い合わせをブロック。クエリログで問い合わせを記録。

試験で狙われるポイント

  • インバウンド = 外（オンプレミス）から入ってくる問い合わせ、アウトバウンド = VPC から外へ出ていく問い合わせ。向きを取り違えさせる選択肢が多い。
  • マルチアカウントでは、エンドポイントは共有サービス VPC に 1 組だけ置き、ルールを RAM で共有するのが運用負荷の低い構成。
  • EC2 上に BIND などの DNS サーバーを立てる案は、動くが運用負荷が高いため不正解になりやすい。
  • DHCP オプションセットでオンプレミス DNS を指定すると、VPC 側のプライベートホストゾーンが解決できなくなる。
