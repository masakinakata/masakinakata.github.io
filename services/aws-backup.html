AWS Backup

EC2、EBS、RDS、DynamoDB、EFS、FSx、S3 など多くのサービスのバックアップを、1 つのポリシーで一元管理するサービス。Organizations と連携して組織全体に適用でき、Vault Lock で削除を防げる。

構成図

仕組みと主な機能

基本の構成要素

  • バックアッププラン：スケジュール、バックアップウィンドウ、保持期間、コールドストレージへの移行、別リージョン / 別アカウントへのコピーを定義する。
  • リソースの割り当て：タグやリソース ID でバックアップ対象を指定する。
  • バックアップボールト：バックアップの保存先。アクセスポリシーと KMS キーで保護する。

削除を防ぐ仕組み

  • Vault Lock（ガバナンスモード）：十分な IAM 権限があればロックを変更・解除できる。
  • Vault Lock（コンプライアンスモード）：猶予期間（最低 72 時間）が過ぎると、root ユーザーや AWS でもロックの解除や保持期間内の削除ができない（WORM）。
  • 論理的にエアギャップされたボールト：AWS が所有するアカウントで管理され、RAM で共有して別アカウントから復元できる。ランサムウェア対策の強化に使う。

組織全体での運用

  • バックアップポリシー（Organizations のポリシーの一種）で、OU やアカウントにバックアッププランを強制する。
  • クロスアカウント管理：委任管理者アカウントから、組織全体のジョブの状況を監視できる。
  • Backup Audit Manager：「すべてのリソースがバックアップされているか」などを監査し、レポートを作る。
  • 復元テスト：定期的に自動で復元を試し、バックアップが使えることを確認する。

「消せない」仕組みの整理

対象仕組み
AWS Backup のバックアップVault Lock（コンプライアンスモード）
S3 オブジェクトS3 オブジェクトロック（コンプライアンスモード）
CloudTrail のログ組織の証跡 + 保存先 S3 のオブジェクトロック
Glacier ボールトGlacier Vault Lock

試験で狙われるポイント

  • 「組織全体にバックアップ方針を強制」→ Organizations のバックアップポリシー + AWS Backup。
  • 「アカウントが侵害されても消されない」→ 別アカウントへのコピー + Vault Lock のコンプライアンスモード。
  • 同じアカウント内の別リージョンへのコピーは、リージョン障害対策にはなるが侵害対策にはならない。
  • Lambda で自前のスナップショット管理を作る案は、動いても運用負荷が高いので不正解になりやすい。
