AWS CloudTrail（組織の証跡）

AWS アカウントで「誰が・いつ・何をしたか」という API アクティビティを記録するサービス。組織の証跡を使うと、全アカウントのログを 1 か所に集約できる。

構成図

仕組みと主な機能

記録できるイベント

  • 管理イベント：リソースの作成・変更・削除など、コントロールプレーンの操作。デフォルトで記録される。
  • データイベント：S3 オブジェクトの読み書きや Lambda の呼び出しなど、量が多い操作。明示的に有効化が必要（追加料金）。
  • Insights イベント：API 呼び出し量やエラー率の異常を検知する。

保存先と保持

  • イベント履歴：何も設定しなくても過去 90 日分の管理イベントを閲覧できる。それ以上残すには証跡か CloudTrail Lake が必要。
  • 証跡（Trail）：S3（任意で CloudWatch Logs）に継続的に配信する。全リージョンを対象にするのが基本。
  • CloudTrail Lake：イベントをマネージドなデータストアに保存し、SQL で直接検索できる。

ログを守る仕組み

  • ログファイルの整合性検証：1 時間ごとにダイジェストファイルを作成し、ログが改ざん・削除されていないかを検証できる。
  • S3 オブジェクトロック：コンプライアンスモードは root ユーザーでも保持期間内の削除や期間の短縮ができない。ガバナンスモードは特別な権限があれば解除できる。
  • SSE-KMS で暗号化し、バケットポリシーで CloudTrail サービスからの書き込みだけを許可する。

試験で狙われるポイント

  • 「全アカウント」「新規アカウントにも自動適用」「メンバーが変更できない」→ 組織の証跡。
  • 「誰も削除できない」→ オブジェクトロックのコンプライアンスモード。バージョニングや MFA Delete だけでは不十分。
  • イベント履歴は 90 日。長期保持の要件があるなら証跡や CloudTrail Lake を選ぶ。
  • Log Archive と Audit を専用アカウントに分けるのが、マルチアカウント構成の定石（Control Tower の標準構成も同じ）。
