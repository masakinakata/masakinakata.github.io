AWS Systems Manager Session Manager

インバウンドポートを開けず、踏み台サーバーや SSH 鍵も使わずに、EC2 やオンプレミスのサーバーにシェル / RDP で接続できる機能。アクセスは IAM で制御し、操作ログも残せる。

構成図

仕組みと主な機能

前提条件

  • インスタンスに SSM Agent が入っていること（Amazon Linux や Windows の多くの AMI にはプリインストール済み）。
  • インスタンスプロファイルに AmazonSSMManagedInstanceCore などの権限があること（またはデフォルトのホスト管理設定を使う）。
  • Systems Manager のエンドポイントへアウトバウンド HTTPS で到達できること。プライベートなら ssm、ssmmessages などのインターフェイス VPC エンドポイントを作る。

主な機能

  • アクセス制御：IAM ポリシーで「誰が、どのインスタンス（タグで指定可）に接続できるか」を制御。
  • ログ：セッションの入出力を S3 や CloudWatch Logs に保存。開始・終了は CloudTrail に記録。
  • 暗号化：セッションのデータを KMS キーで暗号化できる。
  • ポートフォワーディング：ローカルのポートをインスタンス経由でプライベートな RDS などに転送できる（踏み台の代わり）。
  • Windows：Fleet Manager からブラウザで RDP 接続できる。
  • ハイブリッドアクティベーションでオンプレミスのサーバーにも使える。

サーバー接続方法の比較

方法インバウンドポート鍵の管理コマンドログ
踏み台サーバー + SSH必要必要自前で用意
EC2 Instance Connect（エンドポイント）22 番の許可が必要一時的な鍵を自動で配布なし
Session Manager不要不要S3 / CloudWatch Logs

試験で狙われるポイント

  • 「インバウンドポートを開けない」「踏み台を廃止」「鍵管理をやめる」「操作ログを残す」→ Session Manager。
  • インターネット経路のないサブネットでは VPC エンドポイントが必要、という前提条件もよく問われる。
  • Systems Manager にはほかに Run Command（一括コマンド実行）、Patch Manager（パッチ適用）、Parameter Store、Automation などがある。
