AWS KMS（Key Management Service）

暗号化キーを作成・管理し、誰がキーを使えるかを制御するサービス。S3、EBS、RDS など多くのサービスの暗号化を支えている。キーの実体は HSM の外に出ない。

アクセス制御

  • キーポリシー：すべての KMS キーに必須で、アクセス制御の起点。キーポリシーがアカウントに委任していれば、そのアカウントの IAM ポリシーでも許可できる。
  • グラント：一時的・プログラム的に権限を委任する仕組み。AWS サービスが利用者の代わりにキーを使うときによく使われる。
  • 条件キー：kms:ViaService（特定のサービス経由のときだけ許可）や暗号化コンテキストで細かく制御できる。

その他

  • マルチリージョンキー：同じキー素材を複数リージョンで使える。リージョン間でデータを再暗号化せずに復号したいときに使う。
  • S3 バケットキー：S3 から KMS への呼び出し回数を減らし、SSE-KMS のコストを大きく下げる。
  • キーの使用はすべて CloudTrail に記録される。

試験で狙われるポイント

  • クロスアカウントは「キーポリシー」と「利用側の IAM ポリシー」の両方が必要。片方だけの選択肢はひっかけ。
  • SSE-KMS のオブジェクトを読むには s3:GetObject に加えて kms:Decrypt、書き込みには kms:GenerateDataKey が必要。
  • AWS マネージドキーはキーポリシーを変更できないので、クロスアカウント共有には使えない。
  • KMS のリクエスト数の上限やコストが問題 → S3 バケットキー。
  • 専用の HSM を単独で管理する必要がある（FIPS 140 レベル 3 の専有など）→ AWS CloudHSM。
