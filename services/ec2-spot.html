Amazon EC2 スポットインスタンス

AWS の余っている EC2 キャパシティを、オンデマンド料金から最大 90% 程度の割引で使える購入オプション。ただし AWS がキャパシティを必要とすると、2 分前の通知のあとで中断される。

構成図

仕組みと主な機能

中断とその対策

  • 中断の 2 分前に通知される（インスタンスメタデータや EventBridge で検知できる）。
  • それより前にリバランス推奨シグナルが届くことがあり、キャパシティリバランスを有効にした Auto Scaling は代わりのインスタンスを先に起動する。
  • アプリ側はステートレスにする、チェックポイントを保存する、SQS などで処理を再試行できるようにする。

使い方

  • 現在は入札は不要で、価格は需給に応じて緩やかに変動する（上限価格は任意で、省略時はオンデマンド料金）。
  • EC2 Auto Scaling の混合インスタンスポリシー、EC2 フリート、AWS Batch、ECS / EKS、EMR などから使える。
  • 属性ベースのインスタンスタイプ選択（vCPU やメモリの範囲を指定）で、候補のタイプを自動的に広げられる。
  • 配分戦略は price-capacity-optimized が推奨。lowest-price は安いが中断されやすい。

EC2 の購入オプション

オプション割引向いているワークロード
オンデマンドなし短期・予測できない・中断できない
Savings Plans（Compute / EC2 Instance）最大 約 72%1〜3 年の常時稼働。Compute はタイプ・リージョン・Fargate / Lambda にも柔軟
リザーブドインスタンス最大 約 72%構成が固定の常時稼働。Standard / Convertible
スポット最大 約 90%中断耐性あり・時間に余裕がある・タイプに柔軟
オンデマンドキャパシティ予約なし（SP / RI と併用可）特定 AZ のキャパシティを確実に確保したい
Dedicated Hosts—ソケット / コア単位のライセンス、物理サーバーの専有

試験で狙われるポイント

  • 「中断されても再実行できる」「締め切りに余裕」「インスタンスタイプに柔軟」→ スポット。
  • 1 日数時間しか動かないワークロードに RI / Savings Plans を買うと、24 時間分を払うことになり割高。
  • 常時稼働のベースは Savings Plans / RI、変動部分はスポット、という組み合わせが定番の答え。
  • DB やステートフルな単一サーバーなど、中断が許されないものにスポットを選ぶ選択肢は不正解。
