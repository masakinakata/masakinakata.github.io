AWS WAF とオリジン保護

AWS WAF は HTTP リクエストの中身を検査して、SQL インジェクションや XSS などのアプリケーション層（L7）の攻撃をブロックするファイアウォール。CloudFront と組み合わせる場合は、オリジンへの直接アクセスも塞ぐ必要がある。

構成図

仕組みと主な機能

WAF の構成要素

  • ウェブ ACL：ルールの集合。CloudFront、ALB、API Gateway、AppSync、Cognito ユーザープール、App Runner などに関連付ける。
  • ルール / ルールグループ：IP セット、地域、文字列・正規表現、SQLi / XSS 検出、サイズ制限などの条件を組み合わせる。
  • AWS マネージドルール：コアルールセット、SQL データベース、既知の悪性入力、IP レピュテーションなど。AWS が更新するので運用が楽。
  • レートベースルール：同じ IP などから一定時間に大量のリクエストが来たらブロック（簡易的な DDoS・総当たり対策）。
  • アクション：Allow / Block / Count / CAPTCHA / Challenge。まず Count で様子を見てから Block にするのが定石。
  • Bot Control、Fraud Control（アカウント乗っ取り・不正登録の防止）といった有償のマネージドルールもある。
  • 組織全体に WAF ルールを強制したい場合は AWS Firewall Manager。

オリジン保護のパターン

  • ALB オリジン：セキュリティグループで CloudFront のオリジン向けマネージドプレフィックスリストだけを許可し、カスタムヘッダーをリスナールールで検証する。
  • CloudFront VPC オリジン：ALB や EC2 をプライベートサブネットに置いたまま、CloudFront からだけアクセスさせる。
  • S3 オリジン：オリジンアクセスコントロール（OAC）で、CloudFront 経由以外のバケットへのアクセスを拒否する。

防御サービスの使い分け

サービス守る対象動作
AWS WAFL7 の攻撃（SQLi、XSS、ボットなど）ブロック
Shield StandardL3 / L4 の一般的な DDoS自動で緩和（無料）
Shield Advanced大規模 DDoS、DRT による支援、コスト保護緩和・支援（有償）
Network FirewallVPC の出入りの通信ステートフルな検査・ブロック
GuardDutyアカウントやワークロードの脅威検出のみ（ブロックしない）

試験で狙われるポイント

  • 「SQLi / XSS」→ WAF。「DDoS」→ Shield。「検出」→ GuardDuty。
  • プレフィックスリストだけでは他人の CloudFront 経由のアクセスを防げない。カスタムヘッダーと組み合わせる。
  • CloudFront の IP を NACL に手で登録する案は、IP が変わるうえルール数の上限があるので不正解になりやすい。
